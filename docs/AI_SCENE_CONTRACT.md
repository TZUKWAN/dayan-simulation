# AI 助手与场景对应合同

适用范围：大衍本地工作台，2026-11-13。实现入口为 `dayan/agent/agent.py`、`dayan/scene_contract.py` 和 `site/console/results.js`。

## 从需求到画面的路径

1. 解析原始需求，保留模型、数量、位置、参数、步数、种子、干预及缺失约束。明确模型 ID 的命令可直接执行；自然机制描述交给完整规划；具体空间场景进入受约束的新模型构建。
2. 规划器只使用工具提供的真实能力。检索返回实际参数和观测字段；两种筛选分开，支持名称列表。零结果同时说明缺失字段与未满足筛选的候选。搜索后先回填结果，再执行依赖它的动作，禁止占位模型 ID。
3. 新建模型先通过 `design_model` 产出思路、独立缺陷审查、逐项修正、带验收条件的方案、独立方案审查。方案和问题落盘，只有审查通过才进入 DSL 构建。`build_model(request=...)` 可以自动完成全流程，已通过的方案用 `design_id` 继续。大衍核对原始问题、执行选项与数据、DSH 会话及源码版本。主体、状态更新、指标和场景合同使用安全 DSL，场景设施由实际参数或状态表达式驱动。
4. 先验证字段、表达式和行为关联，再由独立的真实 LLM 调用复核需求含义。语义复核不替代计算验证，也不是科学效度认证。失败时修正或明确缺口。
5. 引擎实际运行并保存 manifest、状态帧、观测、事件、checkpoint 和代码版本。助手再核对归档中的主体数、设施和空间结构。环道不能作为十字路口交付；只有汇总值的模型不能画成真实人群。
6. 页面仅回放同一归档的状态。统一 Three.js 呈现器负责灯光、材质、镜头、真实字段图例和设施；助手不自由拼接场景代码。画面、图表、主体详情和时间选择使用同一运行来源。

## 场景中什么可以画

- 主体的数量、坐标、颜色和状态来自保存的状态帧。人物外形与步态由平台呈现。可以用 `visualization.action_by` 和 `action_poses` 将真实取值映射到 `idle`、`walk`、`run`、`sit` 或 `down`。录制时校验取值有对应动作。既有模型可按已知状态或相邻位置变化显示步态。
- 房间、出口、障碍和信号等设施由场景合同导出。声称“参与机制”的设施必须与实际行为规则有关联；参照设施必须明确标记。
- 设施位置和尺寸按逐帧状态更新，不能只在第一帧画一张固定底图。
- 中央工作台用于场地、主体和可回放动作。趋势、仓室状态流和分布放在分析区。汇总记录在中央提示观测范围。
- 平滑回放是在相邻已存档位置之间插值，页面明确标注并允许关闭；不是额外求解出的物理轨迹。统计仍使用实际保存帧。

## 会话、错误和恢复

- 跟进修改按真实 `run_id` 读取模型和有效参数，不能信任客户端传来的矛盾参数。未识别的修改应报告缺口，不能原样重跑后声称已改。
- 解释和能力咨询读取实际归档/工具清单，不为回答问题重跑模型。旧 chat API 使用同一助手链路。
- 继续运行必须恢复 checkpoint、随机流和原时间；不能以从零开始的新运行冒充续算。续算同时修改参数/随机种子的组合目前明确拒绝。
- 整项请求未完成时保持原正确画面，部分实际产物单独供查看，不能配上新需求标题报成功。
- 异步任务落盘并保存真实阶段。已完成任务可在页面/服务重启后恢复；进程中断的运行中任务报告中断，不自动重复付费调用。
- 旧记录无完整状态时只显示实际观测；缺时间戳标记为观测序号，完整报告/续算入口禁用。

## 能力边界

当前自定义 DSL 为单类主体的二维空间或汇总计算，主体数 1–2000、最多 48 个设施，使用有限的安全表达式。不能据此承诺任意三维建筑、烟气/流体/刚体物理、真实交通网络或经过校准的人群疏散。多种子的新模型与定时干预/数据绑定的组合尚未合并实现，会明确拒绝。

场景结构和语义核验能降低错配，无法证明任意自然语言需求已被完整理解，更不能自动证明领域有效性。新增模型仍应使用用户关心的行为性质和实际数据进行对应验收。
