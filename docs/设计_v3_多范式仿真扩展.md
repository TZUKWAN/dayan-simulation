# msim v3 设计：多范式仿真扩展（系统动力学 / 博弈 / 运筹 + 范式耦合）

> 版本：v3 设计稿（2026-11-07）。**纯设计文档，未写代码。**
> 定位：在 v2 五层架构（中立内核/理论包/认知层/测量器具/实验管理）之上扩展，
> 使 msim 成为**多范式统一**的仿真平台——而不是 ABM 平台加几个工具箱。
> 依赖关系：v2 全部验收通过（55/55），本设计完全兼容现有理论包（零破坏）。

## 0. 核心理解：什么叫"系统性全面"

仿真方法论的成熟分类是**四种范式**，各有不可替代的适用域：

| 范式 | 世界观 | 擅长回答 | msim 现状 |
|---|---|---|---|
| **系统动力学 (SD)** | 存量-流量、因果反馈回路、连续 ODE | 宏观结构如何演化、反馈回路主导什么 | ❌ 缺（但 360 题工程有 21 个 ODE 簇可移植） |
| **智能体 (ABM)** | 异质个体、局部交互、涌现 | 微观规则如何长出宏观形态 | ✅ 现有四包全是 |
| **博弈 (Game)** | 理性/有限理性参与人、策略互动 | 激励结构导致什么均衡 | ◐ 部分（投票/抗议是博弈特例，无通用博弈引擎） |
| **运筹/离散事件 (OR/DE)** | 优化、约束、队列、调度 | 资源如何最优配置、瓶颈在哪 | ❌ 缺 |

**关键判断：真正的"系统性全面"不是四引擎并列，而是范式耦合（hybrid）**——真实理论跨层次：马克思是价值形式（微观）+ 积累动力学（宏观）；韦伯是地位互动（微观）+ 合法性结构（宏观）。平台若只能单范式跑，就永远验证不了"微观-宏观传导"这类命题。所以 v3 的旗舰特性是**耦合器**，让 SD 的宏观方程与 ABM 的微观 agent 共享同一世界。

第二条主线：**LLM 在每个范式中的原则性角色**。数学范式中 LLM 不能替代数值计算（三主权第四条：求解器管最优性/数值，LLM 管表述/参与/解释）——这不是限制，而是安全模式（LLM 提案、求解器裁决）。

## 1. 三个新引擎（层0 扩展，学科中立）

### 1.1 EquationEngine（系统动力学）

**声明式存量-流量规约**（YAML，实验即数据的延伸）：

```yaml
stocks:            # 存量（状态变量）
  - {name: 人口, init: 1000, nonneg: true}
  - {name: 资本存量, init: 500, nonneg: true}
flows:             # 流量（速率 = f(存量, 参数, 控制)）
  - {name: 出生, rate: "人口 * 出生率", into: 人口}
  - {name: 投资, rate: "产出 * 积累率 - 折旧", from: 资本存量}
aux:               # 辅助变量
  - {name: 产出, expr: "资本存量 * 0.3"}
links:             # 因果链接（图元数据，带极性，供渲染与分析）
  - {from: 人口, to: 出生, polarity: "+"}
  - {from: 产出, to: 投资, polarity: "+"}
  - {from: 资本存量, to: 产出, polarity: "+"}   # 正反馈回路自动识别
params: {出生率: 0.02, 积累率: 0.25, 折旧: 0.05}
solver: {method: rk4, dt: 0.25}
```

- 求解器：Euler / RK4（scipy 已有，无新依赖）；dt 与 Kernel tick 对齐
- **因果流图自动渲染**：从 links 元数据生成 mermaid/SVG（含反馈回路标识）——你要的"因果流图"是规约的图形化，不是手画
- 不变量：质量守恒（流入-流出=存量变化）、非负存量
- 基准复现：**茶杯冷却**（有解析解，数值验证的黄金标准）、**Lotka-Volterra**（振荡形态）、**Goodwin 增长周期**（工资份额×就业率闭环，马理论宏观的标准模型）

### 1.2 GameEngine（博弈）

**声明式博弈规约**：

```yaml
players: {n: 2, types: [llm, rule, analytic]}
actions: [合作, 背叛]
payoff_matrix:      # [我方动作][对方动作] → (我的收益, 对方收益)
  合作合作: [3, 3]
  合作背叛: [0, 5]
  背叛合作: [5, 0]
  背叛背叛: [1, 1]
structure: {repeated: true, rounds: 50, matching: fixed|random|roundrobin}
information: complete   # complete | imperfect（后续：不完全信息）
```

- **解算器（校准靶，确定性）**：2×N 支持枚举 + 最优反应迭代求纳什均衡；虚拟行动学习作动力学参照
- **LLM 参与人**：自然语言博弈描述 → 行动选择；重复博弈带记忆（上轮双方行动入 prompt）
- **遮蔽变体（理论测试专用）**：prompt 不出现"囚徒困境"等博弈名——测 LLM **是否认出**博弈结构，而非背出教科书答案（这是文献缺口：多数 LLM 博弈论文直接告知博弈类型）
- 基准：PD（互叛纳什）、鹰鸽（混合均衡）、性别战（协调多重均衡）、猎鹿、Axelrod 锦标赛
- 与现有关系：politics 包投票、media 分享都是博弈特例——GameEngine 是泛化，不推翻

### 1.3 OREngine（运筹）

- 线性规划：`scipy.optimize.linprog`（依赖已具备）；整数规划：`scipy.milp`
- 内置问题模板：运输/分配、资源约束下的产出最大化、（后续）离散事件队列
- **propose–dispose 协议**（三主权第四条）：
  1. LLM 读自然语言问题 → 提出分配方案（哪家人分多少）
  2. 确定性求解器验证：可行性（约束满足？）、与最优解的差距（optimality gap）
  3. LLM 解释最优解 vs 自己方案的差异
- 基准：教科书 LP（已知最优解）、运输问题、（后续）M/M/1 解析 vs 模拟

## 2. 理论包接口泛化（层1，零破坏）

`TheoryPack` 增加一个字段：`paradigm: "abm" | "sd" | "game" | "or" | "hybrid"`（缺省 "abm"，现有四包零改动）。

- **sd 包**：提供 `stocks/flows/derivatives` 声明；`kernel.step` = 积分一步
- **game 包**：提供 `matchmake/payoff/strategy_providers`（策略提供者可以是 llm/rule/analytic 三种）
- **hybrid 包**：声明多个子引擎 + 耦合拓扑（见 §3）

七件套纪律不变：所有范式都必须声明不变量（SD：守恒/非负；博弈：动作集成员；OR：约束可行）、校准靶、基准复现题。**没有不变量的包不立项——这条纪律对数学范式同样适用。**

## 3. 范式耦合器 CoupledSimulation（旗舰特性）

把 `run_cross_pack.py` 的手工双包耦合泛化为平台编排器（声明式、共享时钟、多包）：

```yaml
coupling:
  packs:
    macro: {pack: 政治经济学SD包, paradigm: sd, dt: 0.25}
    micro: {pack: 政治经济学包, paradigm: abm, agents: 200}
  exchanges:                    # 每 W ticks 交换一次
    - {from: macro.工资率, to: micro.params.参考工资, transform: identity}
    - {from: micro.劳动力需求聚合, to: macro.雇佣流量, transform: scale(0.01)}
  schedule: {window_ticks: 30, total_windows: 6}
  mode: cyclic                  # one-way（SD环境喂ABM）| cyclic（双向）| reference（SD解析解作ABM对照靶）
```

三种耦合模式：
1. **one-way**：SD 宏观提供环境参数，ABM 微观响应（SD 是"舞台"，agent 是"演员"）
2. **cyclic**：ABM 聚合量反哺 SD 流率——微观涌现驱动宏观演化（真正的多尺度）
3. **reference**：SD 解析/理论轨道作为 ABM 聚合轨迹的 **null model**——"微观涌现 vs 宏观理论"的差异本身就是可发表的量（Goodwin 对照实验）

## 4. LLM 的原则性角色（每个范式都有，但各就其位）

| 范式 | LLM 能做（原则性） | LLM 不能做（主权） |
|---|---|---|
| SD | 从理论文本**引出存量-流量结构**（与专家结构比对的基准）；运行中设定自适应政策规则 | 数值积分、参数计算 |
| Game | 作为参与人博弈（含重复博弈记忆）；自然语言博弈 → 形式化收益矩阵（形式化准确率基准） | 均衡计算（解算器做） |
| OR | 提出分配方案；解释最优解与差距 | 求解 LP、验证可行性（求解器做） |
| ABM | 现状（决策/叙事/量表） | 记账（现状保持） |

三个新的**跨范式基准题**（平台自证）：
1. **"LLM vs Nash"**：LLM 玩家在重复博弈中是否趋向均衡解算器的预测？（文献缺口：已有 LLM 博弈研究直接告知博弈类型，我们做遮蔽版）
2. **"ABM vs SD"**：玩具资本主义的聚合轨迹 vs Goodwin 理论轨道——微观涌现与宏观方程的偏离量是新的可测量
3. **"形式化准确率"**：LLM 把 10 段理论文本转成存量-流量图/收益矩阵，与专家版本比对（这本身就是可发表的方法论贡献）

## 7. 诚实边界（扩展后仍然成立）

1. SD/博弈/运筹是确定性数值范式——LLM 在其中是**表述者/参与者/解释者**，不是计算者；仿真结论的数值有效性由求解器与解析基准保证
2. 范式耦合的"涌现 vs 理论轨道"差异是**测量对象**，不是谁对谁错的裁决
3. 充分性≠必然性、遮蔽设计、机制/趋势分轨——全部纪律自动延伸到新范式
4. 参数敏感性扫描仍是已知缺口（v0/v1 遗留）

## 8. 一次性回答"这和 v2 设计是什么关系"

v2 回答的是"**平台如何承载多学科**"（理论包架构）；
v3 回答的是"**平台如何承载多范式**"（多引擎+耦合器）。
两者叠加后，msim = **多学科 × 多范式 × LLM 语义**的仿真基础设施——
学科轴（政治经济学/社会学/政治学/文化/组织）× 范式轴（SD/ABM/Game/OR）× 方法轴（LLM/规则/解析）的组合空间里，任何一格都可以声明式立项。
