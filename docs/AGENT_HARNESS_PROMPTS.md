# 大衍 Agent 提示词与执行证据

消融科学声明与实现分阶段：模型未选定时，prepare使用`binding={"kind":"approved_plan"}`，先冻结参数、机制、输出、尺度及判据。后续plan的`diagnostic_bindings`逐原id给真实演化`rule_refs/reason`，独立review逐项给`diagnostic_checks`；缺失、支撑/帧路径、非advance可达函数均不能通过。编译只按获审映射解析，MS保存原科学声明、实际路径、方案和模型定义hash。已给明确`rule_refs`的旧协议保持严格核对，不静默改写原MI，不为通过添加伪调用。

复杂原生参数可以使用`arguments_path`：Agent按真实schema编写参数，以JSON序列化保存项目内UTF-8 envelope `{"tool":"实际工具名","arguments":{完整参数}}`，然后`dayan({action:"execute",tool:"同一工具名",arguments_path:"parameters.json"})`。不混用inline或其他顶层参数；宿主验证路径/工具名并返回原字节hash，只读取JSON，不执行内容；全部后台验证保留。原生prepare的question可省略，protect从当前真实用户消息逐字绑定；独立HTTP schema仍要求question。复杂目标/诊断及多行源码不再需要抄进同一工具调用字符串。

项目内dayan分派前的MALFORMED_RESPONSE由原生agent/request-error seam做同turn/step最多5次定向恢复。日志保留原失败，模型实际接收带来源标记的上下文；source.kind明确不同于user，原文绑定不改变。其他项目/工具/错误、取消或卸载不接管。普通developer文字在当前适配器实测未投影到模型，故采用受归属的user/context消息；以真实请求字节及会话日志核可见性，不以落盘代替模型收到。

该单元已有6项文件/桥接检查、2项恢复协议检查，以及真正安装版DSH＋明确标记的本地故障注入提供方＋实际Python健康服务验收（native-argument-recovery-03）：实际exit0，同step收到一次恢复上下文、一次有效分派、原用户消息不变、原失败保留，全部自有进程已结束。01/02失败证据保留。此受控传输验收不是云模型科研或完整系统通过，原研究仍须独立原生验收。

当前合同修复：`execution.delivery`向所有设计阶段及语义复核提供真实状态/归档API、工作台URL和恢复控制器，科研明确使用所选参数结果和同MS的`research_report`。这些是实际接口说明，仍需运行后核对同源结果。`research_model_prepare`在设计前复用诊断声明校验，schema用oneOf给完整模式；模型生成后再查参数范围及方程路径。`dynamics`只能为deterministic或ensemble_moments，后者至少两个seed；不填观测名或裸函数路径。

方案`blocked`以保存的否决生成有父版本的定向修订，保留同MI/原文/会话/数据/阈值，复用有效构思与批评，重新修订方案并独立审查。旧版不覆盖；未获批的构建只返回正确下一步，不执行。模型结构或后续科学检验实际失败仍保留失败，不把恢复入口当通过证据。

DSH 把一条完整用户消息绑定给大衍。各阶段直接收到同一份原话。引文编号只记录方案与原话的对应位置。会话、原话、实参设置和执行版本共同进入方案校验。

时钟与数据口径：每次真实LLM调用增加平台实际UTC系统时钟，计入预算/请求hash并写入审计；modeling_guide也给本次工具回执时钟。它们不是仿真年份或数据发布时间，后续采集正常晚于早先工具回执。target_sources附已核目标DS的实际retrieved_at。time_origin绑定标签可省略继承统一标识，显式冲突仍拒绝；实际日期偏移与单位检查不放松。prepare提供完整data_bindings schema；scope字段只放地区/群体标识，匹配仅为declared_match，不能把两个相同的说明文字当作已核验全部原始成员。

### 在线文献

科研和政策仿真在独立构思后，以通用中英文关键词调用 OpenAlex、Crossref 和 arXiv。系统读取可访问的原文网页或在线 PDF，通过题名、DOI 和正文段落校验身份及可读性。引用记录保留版本、实际访问地址、时间、内容哈希、章节或页码。论文原件只在读取过程中驻留内存。

精读目标为 5–10 篇相关期刊论文，显示实际读到的数量。期刊官网的收录说明和 OpenAlex 来源目录分别记录；arXiv 预印本可补充方法但单列。收录来源反映核验时的目录信息。只读到摘要、未找到全文、服务异常及证据不足都有实际回执。公开入口未覆盖的订阅文献受相应访问权限限制。

精读记录区分作者陈述、根据原文的推断和未核实信息。计划把来源连接到实际机制、参数或数值验证条件。独立审查核对适用性，与原文要求或本地校准的数据冲突时指出具体差异。建模方案的指纹绑定文献和取舍，Word 从已归档方案读取同一份证据。

检索提供方、每篇在线正文读取、每篇论文审核和跨论文综合分别保存独立阶段及hash；续接复用已接受结果，原HTML/PDF不作为本地全文下载保存。逐篇审核避免一次塞入整批正文导致上下文和预算互相挤占；合并时重新分配全局E编号，保持P编号、实际定位和段落hash一致。无关论文可以排除，预印本与期刊索引数量分别记录。默认5–10篇为研究目标；不足时保留补查方向并以实际依据、显式假设和数值检验继续建模，不自动增加拒绝门槛。用户明确指定的证据仍须按原话补齐。

同一结论可定位多段正文，section接受实际编号列表或逗号分隔，逐段保留定位与hash。阶段响应若仅漏写数组元素对象的右括号，系统只插入该缺失分隔符，原始响应、错误和规范化hash进入审计；字段内容不改，原有schema/来源/科学审核继续执行。截断、坏字符串、重复键等不会被这种格式恢复伪造成有效结果。

| 修订 | 回应每个问题，对执行缺口保留对应证据 | 修订后的设计与待解决缺口 |
| 实施方案 | 将公式、作用域、数据绑定、观察量和事前数值判据连接起来 | 可执行方案及引用 |
| 独立审核 | 逐式核查原文和判据。有可用时间时请求模型使用推理模式 | 独立审核回执 |

提示入口在 `plugins/dayan/host/tools.js`。阶段模板和 DSL 合同在 `dayan/agent/model_prompts.py`。阶段调用与批准校验在 `dayan/agent/model_design.py`。工作台从真实归档取数。

常规建模续接使用next_action内的continuation_token与design_id。完整参数保存在内容寻址的同会话任务记录中，先核原文/会话/版本/摘要再进入正常设计或构建入口；已完成阶段复用，所有数据/方程/数值审核保持。不能把续接变成重抄几十个参数、舍入真实输入或另起自己的模型。需要修改自拟设置时走显式方案修订。

自主编写实现时，validate_model/build_model允许在同一build续接凭据上附加definition（原生也支持definition_path）。凭据只恢复原方案、数据、时钟和参数；新增实现仍走原有代码预检、独立语义审核与真实数值验收，不把合法实现提交误当成运行设置篡改。

研究构建等待与数值执行限时分开：design_model/build_model/reviewed_run默认每次调用900秒，独立阶段取得该预算内的完整推理等待时间；不再以固定176秒截断复杂审核。TaskManager记录并实际监督该次预算，原生HTTP等待覆盖它；取消、CPU/内存/磁盘与数值求解器原预算保持。DAYAN_AUTHORING_WALL_SECONDS可显式调整（最多3600秒）；仅设置旧DAYAN_WALL_SECONDS时继续尊重该操作员约束。定向测试用受控时钟加真实自有子进程验证监督，不等同于真实云模型已通过。

自建基线完成后的配对对照通过experiment(baseline_run_id,arms,metric,seeds)执行；平台核真实已审基线、方程身份、原输入与原时钟，处理变化明确列为对照。原用户问题与模型来源分别保存，全部成员真实推进后进入同experiment_id报告。变体保留原模型设计的来源指针，不冒称原基线数值判据已对所有变体重新通过。MI研究不能借此绕过冻结校准与留出；零/负效应照实保留。

默认编排只有一条方案链：design_model收到原始需求时通常省略尚未确定的parameters，由设计明确真实取值。pending直接调用next_action，不附加等待或重做；approved后以同design_id和运行设置build_model，默认不传definition，让编译阶段落实完整获审方案。手写实现仍可用，但先读全design_details，再对同一definition_path依次预检和构建。运行参数与类型/default/unit定义分开，避免外层Agent先编一套模型、内层规划器又编另一套。

调整Agent自拟取值时，design_model(revise_from=原编号,revise_proposal=true)保留原文、用户固定参数、会话与MI科研协议，生成独立重审的新版本；旧版和已读文献保留。program的准入按真实接口，不套用DSL的专题限制。整组对照/多种子报告通过report_run传实际成员run_id及experiment_id或analysis_id（二选一），同组全部运行参与分析，不能把单条轨迹当重复统计。

自建模型方案把每个演化机制和实际方程路径写在同一条记录。数值观测使用最终由 DSL 导出的字段名，单位与含义另写。种子、时钟、干预、主体状态和报告由各自的执行记录提供证据。通过 `design_model` 后，DSH 可以直接调用回执中的 `next_action`。同一会话的同一条用户消息内，调用 `build_model` 时若省略方案编号和规约，且传入的运行设置与获批设置一致，宿主补全该方案及其设置，由后端再次核对绑定。

能力检索返回的是执行事实。编制前给定模型或适配器的输入、更新方式、实际输出及已核验的证据。固定网格尺寸、编号和导出字段可引用实际结构。步长、干预、随机种子和保存的逐主体帧使用实际执行证据，推进状态的规则仍需有效方程。关键机制仍然缺失时，保留模型范围、缺失机制和待验证条件。用户提出的对照结构、科研假设和现实外推各自接受核验。

### 仿真规模

modeling_guide 提供原文规模、当前可用内存与受管工作进程预算。容量是参考估计，规约编译后按实际字段、邻域、历史写入深度和机器余量预检。指定人数和长宽直接核对。要求尽可能大而没有指明人数时，在已审查方案中确定 population_target，并按实际定义校验。涉及额外专用物理或人工智能推理的模型仍按对应执行器的合同核对真实上限。

大规模 DSL 用同步列式推进，支持矩形周期网格和普通二维主体。标量兼容模型沿用原随机流。列式模型的种子复现和检查点延续采用同一列式取样顺序。运行包中的 state_frames.population 保存完整列、规模与编码。固定网格的主体编号按行优先，坐标由行列直接生成。一条局部统计查询覆盖本格之外的整个四邻或八邻，读取 lag=0 时的旧状态或指定历史。常量、二元和整数列使用可逆省空间编码，连续值保留 Float64。worker 在预算内保留完整初末状态及可负担的中间时点，数值观测每步读取全人口。明确要求逐步全量状态时验证每一步归档。

运行包同时保存运行和检查点。回放单独提供有界真实样本或规整网格分区均值，独立报告可以直接从全量状态列计算空间统计。不要以回放样本数宣称实际规模。

多种子和多情景批次同时记录父归档和各次实际运行。超过 DSH 工具正文传输范围时，保留各 `run_id`、状态地址与整批数据下载地址。报告仍按单次真实运行生成，会话凭据只允许访问本会话产生的归档或用户明确指定的运行。

## 自建模型科研入口的当前边界

`research_model_create`已提供从当前版本已审查且实际数值验收通过的基线运行创建MS研究的公开工具。模型定义、批准方案、原始需求、输入映射与基线归档hash写入固定协议；对大归档流式校验文件，避免为创建研究加载所有主体历史。目标DS映射、三分区、尺度、网格、重复及诊断在求值前固定。MS研究通过`research_calibrate`续接同一编号，再用同号`research_report`导出；旧ST趋势入口保持原协议。原生用户须明确基线编号或使用同原始任务、同会话实际基线。

新用户原文同时要求自主建模与校准时，`research_model_prepare`先固定MI研究意图：完整原文/原生会话、真实目标DS与输入、目标名和单位、时钟、三分区、目标尺度、参数网格、种子、阈值和诊断。内层建模提示只附训练值及目标来源/计数，验证/留出值不被送入建模提示。`design_model/validate_model/build_model/revise_from`全程保留MI；方案将后续研究职责绑定MI，基线审查与数值检查完成后标model_ready，不能称整题完成。

实际基线自动接同MS求值；中断恢复不重复已归档基线或已经完成的试验。`research_calibrate`沿同号next_action执行训练、验证选型、事前诊断和最后留出。`research_finalize`使用所选参数和事前第一个seed实际运行完整状态，逐观测复现同研究试验，单独归档结果run_id；大屏与Word/图/复核包使用该结果，而非默认参数基线。单seed不是多seed均值动画。报告保留失败结论，工具执行成功与科学通过分开。受控协议和真实数学执行已验收，实际安装版DSH公开数据研究仍须独立端到端验收，不能以这些测试代替。

来源文字用`research_model_context`：先真实采集原件，按同MI提供DS/JSON Pointer、用途和适用观测，平台读取实际文字/hash后交给独立复审及同源Word/原件包。不会改变科学协议或把背景文字变成数值输入。设计前或blocked后可追加，已运行不允许悄补。`execution.research.target_integrity`描述真实已选目标的时点数量、起止、间隔与原件核验，审查按原文检查覆盖；沙箱模型不为此接收验证/留出目标值。它不证明发布时点、代表性或因果有效。

## 研究记忆

新研究从完整用户原话独立形成思路。第一版思路写入方案记录后，缺陷审查可以看到相关历史，查找范围以内置的原生会话归属和项目为准。历史资料只在审查阶段呈给模型，当前研究的机制、实参、数据绑定和验收由原话与本轮方案决定。明确要求按旧模型继续修改时，仍生成绑定真实 `last_run.run_id` 的方案。

只有通过本轮执行验收的自建模型运行进入可检索索引。索引记录模型和运行编号、运行版本、机制、时间口径、数据字段及核验层级，引用时读取真实归档的方程。系统使用中文词组与英文术语匹配，返回最多三个相关模型版本。科学校准标志取自真实记录。未归属的老数据仍可按实际编号查看，已删除和清空的历史退出自动参考。

DSH 使用配置与项目路径形成稳定归属。同项目新对话可以检索以前的成功运行。旧宿主可用已绑定的项目会话，缺少工作区信息时按会话隔离。独立工作台按其本机数据目录维护自己的索引。新任务可自建时，默认建模导航直接给独立建模入口。原生模型目录、指定模型运行和专用求解入口继续可用。
